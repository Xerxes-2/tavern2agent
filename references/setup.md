# 开局 setup

`first_mes` 在酒馆是直接注入的。但在 agent 环境中，很多卡在叙事开始前**需要信息才能运转**——可能是用户角色定义、可能是难度/参数选择、可能两者都有。这些缺失信息由 agent 在开局时**主动向用户索要**。

---

## 分析：缺失信息清单

分析阶段扫描以下信号，汇总成一张清单：

| 检测信号 | 位置 | 含义 |
|----------|------|------|
| 世界书有 `{{user}}设定`/`{{user}}人设` 条目 | 世界书 entry comment | 卡片定义了用户角色模板，需提取已知字段，标记缺失字段 |
| `first_mes`/`description` 含 `{{user}}` 占位，但世界书无定义 | 卡片主字段 | 卡片期望用户有角色身份，但未定义——开局时需询问 |
| `first_mes` 末尾是问句/选项/配置引导 | `first_mes` | 卡片设计了开局选择（难度、路线、起始状态等），需用户决策 |
| world book 有描述"开局设置"的条目 | 世界书 | 同上 |
| `first_mes` 是纯叙事，无占位无问句 | — | 无缺失信息，开局直接叙事 |

---

## 产出：开局 skill

每个卡片迁移**必须产出** `skills/开局.md`。这是游戏的入口 skill。

### 模板

```markdown
---
name: 开局
description: 开始/重新开始游戏。收集缺失信息后交付开场叙事。
---

# 开局

你是 {{角色名}} 世界的 GM。用户请求开始游戏。

## setup

在输出任何叙事之前，检查以下信息是否已就绪。缺失的逐项向用户索要：

{{setup_checklist}}

## 开场

所有信息集齐后，基于 `narrator.log` 展开场景，输出开场叙事。不要复述原文，让用户立即进入角色。
```

### `{{setup_checklist}}` 生成规则

从缺失信息清单逐条翻译：

| 清单条目 | checklist 文本 |
|----------|---------------|
| 无缺失 | 无需额外信息，直接进入开场。 |
| user 卡缺失字段 | `用户角色缺少 [字段名]，请向用户询问。已知：[已有字段列表]。用户提供后写入 data/user.json。` |
| user 卡完全缺失 | `用户角色未定义。请向用户询问：姓名、性别、年龄、外貌、性格、背景。提供后写入 data/user.json。` |
| 开局选项 | `开局需要用户选择：[列出 first_mes 中的选项]。请逐项询问。` |
| 多条目 | 合并为一条 checklist，逐条列出。 |

### 用户直接调用

用户可以随时对 agent 说「开局」来重新开始游戏。

---

## 平台集成

### pi

extension 负责 system prompt 注入 + 工具注册。用户说「开局」后 agent 读 skill 文件执行。

### Claude Code

`/init` 加载 `agents/gm.md`，用户说「开局」后 agent 读 skill 文件执行。

流程：

```
用户说「开始」/ 首轮触发
        │
        ▼
  agent 读 skills/开局.md
        │
        ▼
  ┌─ setup 阶段 ───────────────────────────┐
  │ 按缺失清单逐项向用户索要：                │
  │  · user 卡缺失字段？→ 询问              │
  │  · 开局选项？→ 让用户选择               │
  │  · ...                                  │
  │  全部集齐 → 继续                         │
  └─────────────────────────────────────────┘
        │
        ▼
  agent 读 narrator.log，交付开场叙事
```
